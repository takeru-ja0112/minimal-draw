# 自由描画（フリーハンド）モード追加 実装計画

- 作成日: 2026-08-26
- 更新日: 2026-08-26（将来の汎用化を見据えた設計方針を追記）
- 対象: 当面は「お題無しの気軽にお絵かき画面」（デモ描画ページ）限定でのフリーハンド描画ツール追加。ただし将来的に別の新機能として汎用化（デモ以外の画面でも使えるように）される前提で、それに対応しやすい設計にする。

## 1. 背景・要件

- 現状の描画機能は `line`（直線）/ `circle`（円）/ `rect`（長方形）/ `eraser`（消しゴム）/ `move`（移動）の固定図形ツールのみで、自由に線を引く（マウス/指の軌跡をそのまま描画する）ことができない。
- 今回追加したいのは、マウス/タッチの軌跡をそのままなぞって描ける「自由曲線（ペン）」ツール。
- **今回の表示対象は「お題無しの気軽にお絵かきできる画面」（デモページ）に限定する**。お題ありのゲーム本編（ルーム対戦モード）にはフリーハンドツールを出さない。
- **ただし、これは恒久的な制約ではなく「現時点でオンにする画面がデモページだけ」という運用上の初期値に過ぎない**。将来、別の新機能（例: 自由お絵かき専用の新モード、共同編集モードなど）としてフリーハンド描画を汎用化する計画があるため、「`mode === 'demo'` かどうか」という特定の文字列比較にロジックを直接結びつけない設計にする（詳細はセクション3.1）。
- 既存のツールアイコン群と同じ場所に、新しいアイコンとして追加する。

## 2. 現状構造の整理

### 2.1 モード分岐の仕組み（既存）

- `app/drawing/page.tsx`: `<DrawPage roomId={固定ダミーUUID} mode="demo" />` として「試し書き」ページを提供済み。
- `components/pages/DrawPage.tsx`: `mode === 'demo'` の分岐で `SaveControl` / `ThemeModal` / `ThemeHeader` などお題・保存系UIを非表示にしている。
- ルーム対戦モード（`app/room/[id]/drawing/page.tsx`）は `mode` を渡さず、通常フロー（お題あり・DB保存あり）で動作する。

→ `mode === 'demo'` の分岐は「お題・保存系UIの出し分け」という既存の役割のまま維持する。フリーハンドツールの表示可否については、この `mode` 分岐に相乗りさせず、セクション3.1で述べる独立したprops（`enabledTools`）で制御する（将来の汎用化に備えるため）。

### 2.2 ツール追加の基本パターン（`rect` ツールを踏襲）

新規ツール追加時に触るファイルは次の5箇所（`rect` ツールの実装がそのままテンプレート）。

1. `type/DrawShapeType.ts` — `ToolType` Union、形状の型定義
2. `constants/drawTools.tsx` — ツールバーに表示するアイコン定義（配列に追加するだけでUIに出現）
3. `hooks/DrawPage/handleDraw.ts` — マウス/タッチイベント処理、state・履歴管理、保存処理
4. `components/organisms/draw/DrawCanvas.tsx` — Konvaでの実描画
5. 保存・閲覧系の型/パーサ（`app/room/[id]/drawing/action.ts` の `CanvasData` 型、`lib/admin/parseCanvasData.ts`、管理画面/ミュージアムのプレビュー数箇所）

ただし今回は **デモページのみで完結し、DB保存は行わない**（`handleSave` はデモモードでは呼ばれない = `SaveControl` 非表示のため）ため、5番の保存・閲覧系対応は**不要**。この点が実装コストを大きく下げるポイント。

## 3. 実装方針

### 3.1 ツール表示の出し分け（汎用化を見据えた設計）

- `constants/drawTools.tsx` の `drawTools` 配列に `pen`（自由曲線）エントリを追加する際、単純に配列へ足すと全画面（ルーム対戦モードも含む）に出てしまう。
- **`mode === 'demo'` を直接の判定条件にはしない**。理由: 将来「自由お絵かき」が別の新機能として独立した場合、その新モードは `'demo'` ではない別の `mode` 値（あるいは `mode` という概念自体を持たない新画面）になる可能性が高く、`mode === 'demo'` 決め打ちだと汎用化のたびに条件分岐を書き換える羽目になるため。
- 代わりに、**「どのツールを有効にするか」を呼び出し元（ページ）が明示的に指定できるprops**を新設する。
  - `type/DrawShapeType.ts` に `export type ToolType = 'line' | 'circle' | 'rect' | 'eraser' | 'move' | 'pen';` を定義した上で、
  - `DrawPage` に `enabledTools?: ToolType[]` という任意propsを追加する（未指定時は既存の固定図形ツール一式 `['line', 'circle', 'rect', 'eraser', 'move']` をデフォルトとし、既存呼び出し元＝ルーム対戦モードには一切影響を与えない）。
  - `app/drawing/page.tsx`（デモページ）からは `<DrawPage roomId={...} mode="demo" enabledTools={['line', 'circle', 'rect', 'eraser', 'move', 'pen']} />` のように明示的に `pen` を含めて渡す。
  - `components/organisms/draw/ToolSelector.tsx` は `drawTools` 配列を `enabledTools` で `filter` して表示するだけのシンプルな役割にする（`mode` という概念を一切知らなくてよい）。
- この設計により、将来「自由お絵かき専用の新モード」画面ができた場合も、その画面から `enabledTools` に `pen` を含めて `DrawPage` を呼び出すだけで機能を有効化でき、`mode` の値や `DrawPage`／`ToolSelector` 内部のロジックを変更する必要がない。
- `drawTools` 自体（アイコン定義配列）は「有効化されうる全ツールのカタログ」という位置づけのまま定数配列で維持し、フィルタリングは呼び出し側のpropsに委ねる（カタログとポリシーを分離する）。

### 3.2 型定義の拡張（`type/DrawShapeType.ts`）

```ts
export type ToolType = 'line' | 'circle' | 'rect' | 'eraser' | 'move' | 'pen';
export type FreeLineShape = number[]; // [x1,y1,x2,y2,x3,y3,...] 可変長の点列
```

- `lines: number[][]` と同じ「フラット座標配列の配列」という構造を流用できるため、新規に `strokes: number[][]` という別stateとして持つ（直線ツールの当たり判定・移動ロジックと衝突させないため、`lines` とは分離管理）。

### 3.3 描画ロジック（`hooks/DrawPage/handleDraw.ts`）

- state追加: `const [strokes, setStrokes] = useState<FreeLineShape[]>([])` + 履歴用ref `strokesHistory`
- `pushHistory` のシグネチャに `nextStrokes` を追加し、他図形と同様にUndo/Redo対象にする
- `handleMouseDown`: `tool === 'pen'` のとき、`strokes` に新規ストローク `[x, y]` を1件push
- `handleMouseMove`: `tool === 'pen'` のとき、**末尾ストロークに現在座標を追加（concat）**する。既存の `rect`/`circle`/`line` が「末尾要素を置き換える」実装なのに対し、ここが唯一の差分ポイント。
- `handleMouseUp`: 既存の共通確定処理（履歴確定）にそのまま乗せる
- `eraseAtPoint` / `getNearestShape`: フリーハンドは可変長の点列のため、既存の「2点固定（`line[0..3]`）」決め打ちコードは使えない。ストローク内の全セグメントをループして距離判定する処理を追加。
- `handleReset`: `strokes` も併せてクリア対象に含める

### 3.4 描画レンダリング（`components/organisms/draw/DrawCanvas.tsx`)

- `strokes.map((points, i) => <Line key={i} points={points} ... />)` を追加。既存の `line` 用 `<Line>` と同じKonvaコンポーネントを流用できるため実装コストは低い。
- 線のスタイル（太さ・色・`lineCap="round"` / `lineJoin="round"` / `tension` によるスムージングなど）は既存 `line` と差別化する場合はここで調整。

### 3.5 保存・DB連携について

- デモページでは `SaveControl` が非表示＝`handleSave` が呼ばれないため、**DBスキーマ変更・`CanvasData`型拡張・管理画面/ミュージアムのプレビュー対応は今回不要**。
- 将来的にデモページの絵をDB保存する機能を追加する場合は、上記セクション2.2の5番（`action.ts`の`CanvasData`型、`parseCanvasData.ts`、プレビュー3コンポーネント）に `strokes` を追加する対応が別途必要になる。今回のスコープ外として明記する。

## 5. 動作確認観点

- デモページ（`/drawing`）: ツールバーに自由曲線アイコンが表示され、ドラッグした軌跡通りに線が描かれること
- ルーム対戦モード（`/room/[id]/drawing`）: 自由曲線アイコンが表示されないこと（お題ありモードには影響を与えない）
- Undo/Redo・全消去（Reset）が `strokes` にも正しく反映されること
- 消しゴムツールでフリーハンドの線を消せること、移動ツールでフリーハンドの線を選択・移動できること（対応する場合）
- モバイル（タッチ操作）でも軌跡通りに描画できること（既存の `line` ツールがタッチ対応しているか要確認、`onTouchMove` 等のハンドラ共通化状況をあわせて確認する）

## 6. 未決事項（実装着手前に確認したいポイント）

1. **消しゴム・移動ツールのフリーハンド対応**: 自由曲線を消しゴムで消せる/移動ツールで動かせる必要があるか、それとも自由曲線は「描いたら固定」で構わないか（対応要否でセクション3.3の実装量が変わる）
2. **線のスタイル**: 直線ツールと見た目を変える（太さ・色・スムージングの有無）か、既存の線と統一するか
3. **将来のDB保存対応の要否**: 今回はデモページ限定・保存なしで進めるが、将来汎用化する際に保存/共有まで必要になるか（セクション3.5参照。必要になった時点で `CanvasData` 型等に `strokes` を追加する想定で、今回は型・保存経路には手を入れない）
